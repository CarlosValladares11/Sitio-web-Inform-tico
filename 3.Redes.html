1. Direcciones IP, Direccionamiento Lógico, Subnetting y el Sistema DNS Avanzado

El direccionamiento en redes de computadoras es el pilar fundamental que permite la identificación unívoca de nodos dentro de una infraestructura local o global. Sin un sistema de direccionamiento estructurado, los datos flotarían en la red sin un destino verificable.

1.1 Evolución del Protocolo IP: IPv4 vs. IPv6

  • IPv4 (Internet Protocol version 4): Utiliza direcciones de 32 bits divididas en cuatro bloques numéricos llamados octetos (separados por puntos, ej. 192.168.10.50). Su capacidad matemática máxima es de aproximadamente 4,320 millones de direcciones únicas, un espacio que se agotó oficialmente a nivel mundial debido a la masificación de dispositivos inteligentes.
  • IPv6 (Internet Protocol version 6): Desarrollado para solucionar el agotamiento de direcciones mediante un esquema de 128 bits expresado en notación hexadecimal y agrupado en bloques separados por dos puntos (ej. 2001:0db8:85a3:0000:0000:8a2e:0370:7334). Permite un número casi infinito de direcciones (340 undecillones), integrando seguridad IPsec de forma nativa.

1.2 Mecanismos de Configuración y Segmentación (DHCP y Subnetting)

  • Servidor DHCP (Dynamic Host Configuration Protocol): Protocolo de la capa de aplicación que asigna automáticamente parámetros de red (dirección IP, máscara de subred, puerta de enlace predeterminada y servidores DNS) a los equipos que se conectan, evitando configuraciones manuales propensas a errores.
  • Subnetting y Máscaras de Subred: Proceso matemático mediante el cual una red lógica grande se segmenta en subredes más pequeñas y manejables utilizando una máscara de subred (ej. 255.255.255.0). Esto reduce el tráfico de difusión (broadcast), aísla fallos de red y mejora drásticamente los niveles de seguridad interna.

1.3 El Sistema de Nombres de Dominio (DNS - Domain Name System)

Los seres humanos memorizan nombres alfanuméricos intuitivos (como unah.edu.hn o google.com), pero los enrutadores operan estrictamente con direcciones IP numéricas. El DNS actúa como la "agenda telefónica global de Internet" realizando esta traducción en milisegundos a través de una jerarquía de servidores raíz (Root Servers), servidores de dominio de nivel superior (TLD como .com o .hn) y servidores autoritativos.

> FLUJO DE RESOLUCIÓN DNS:
1. Cliente solicita: "www.sitio-educativo.edu"
2. Consulta al Servidor DNS Local (ISP o Router)
3. Búsqueda en Servidores Raíz (Root Name Servers)
4. Redirección al Servidor TLD (.edu) y Servidor Autoritativo final
5. Respuesta devuelta al Cliente: IP 172.217.14.206 (Conexión establecida)

2. Arquitectura de Red, Modelo Cliente-Servidor y Modelos de Capas (OSI / TCP-IP)

Para que dispositivos informáticos de diferentes marcas, arquitecturas y sistemas operativos puedan comunicarse sin conflictos, la industria tecnológica estandarizó los procesos de comunicación mediante modelos por capas y arquitecturas distribuidas.

2.1 Paradigma Cliente-Servidor vs. Redes Peer-to-Peer (P2P)

  • Arquitectura Cliente-Servidor: Modelo centralizado donde los clientes (computadoras, navegadores, smartphones) realizan peticiones de recursos o servicios, y los servidores (computadoras de alto rendimiento que operan 24/7) procesan dichas solicitudes, almacenan bases de datos y devuelven respuestas estructuradas.
  • Redes Peer-to-Peer (P2P): Arquitectura descentralizada donde cada nodo de la red actúa simultáneamente como cliente y como servidor, compartiendo recursos directamente sin necesidad de un servidor central intermediario (ej. redes de intercambio de archivos BitTorrent).

2.2 Modelo OSI (Open Systems Interconnection - 7 Capas)

Marco de referencia teórico creado por la ISO para conceptualizar cómo viaja la información estructurándola en 7 niveles independientes:

  • Capa 1 - Física: Transmisión de bits crudos a través de medios físicos (cables de red UTP Cat6, fibra óptica, ondas de radio Wi-Fi).
  • Capa 2 - Enlace de Datos: Control de acceso al medio y direccionamiento físico mediante direcciones MAC e identificación de tramas.
  • Capa 3 - Red: Direccionamiento lógico global (IP) y selección de la mejor ruta de transporte de paquetes entre redes distintas (Routers).
  • Capa 4 - Transporte: Garantía de entrega de datos, control de flujo y corrección de errores mediante protocolos fundamentales como TCP y UDP.
  • Capa 5 - Sesión: Apertura, mantenimiento y cierre de las sesiones de comunicación interactiva entre aplicaciones distribuidas.
  • Capa 6 - Presentación: Traducción, compresión, sintaxis de datos y cifrado/descifrado de la información legible para el usuario.
  • Capa 7 - Aplicación: Interfaz directa de software donde operan los protocolos de usuario final (HTTP, FTP, SMTP, DNS).

2.3 Modelo TCP/IP (El Estándar Práctico de Internet - 4 Capas)

Modelo real simplificado que fusiona las capas del modelo OSI para adaptarlas a la implementación operativa de Internet: 1. Acceso a Red (Física y Enlace), 2. Internet (Capa de Red IP), 3. Transporte (TCP/UDP) y 4. Aplicación (Servicios web y correo).

3. Anatomía de Internet, Ruteo de Paquetes y Conmutación de Tráfico

Internet no es una estructura monolítica, sino un "sistema de sistemas autónomos" interconectados a escala planetaria. La información digital nunca viaja en un flujo continuo de principio a fin, sino que experimenta un proceso físico y lógico sumamente dinámico.

3.1 Conmutación de Paquetes (Packet Switching)

En lugar de mantener un circuito telefónico dedicado (como las redes analógicas antiguas), la información digital se divide en pequeños bloques normalizados llamados paquetes. Cada paquete contiene la cabecera con la dirección de origen, destino y número de secuencia. Viajan por rutas independientes y cambiantes a través de la red, y al llegar al equipo receptor, el protocolo de transporte los reensambla en su orden correcto.

3.2 Enrutamiento (Routing) y Protocolos de Pasarela

  • Routers (Enrutadores): Dispositivos inteligentes de la capa de red que conectan redes heterogéneas. Analizan las cabeceras IP de los paquetes entrantes y toman decisiones de reenvío basadas en tablas de rutas dinámicas (Salto a Salto u Hop-by-Hop).
  • Protocolos de Enrutamiento IGP y EGP: Protocolos como OSPF (Open Shortest Path First, utilizado dentro de una misma organización) y BGP (Border Gateway Protocol, el protocolo troncal que rige las interconexiones globales entre los grandes proveedores de Internet o ISPs).
  • Backbone Global de Internet: Infraestructura masiva de cables submarinos de fibra óptica transoceánica y centros de intercambio de datos (IXP - Internet Exchange Points) operados por operadores de Nivel 1 (Tier 1).

4. Protocolos Web: HTTP vs. HTTPS y Criptografía Avanzada SSL/TLS

La capa de aplicación es la encargada de gestionar la interacción directa con el usuario a través de navegadores web. La diferencia fundamental en la ciberseguridad actual radica en cómo se transfiere esta información entre el cliente y el servidor web.

4.1 HTTP (Hypertext Transfer Protocol - Puerto 80)

Es el protocolo fundacional de la Web desarrollado por Tim Berners-Lee. Su principal limitación crítica es que transmite todos los mensajes, credenciales de usuario (contraseñas) y formularios en formato de texto plano (Plain Text). Cualquier atacante con herramientas de escucha de red (Sniffers como Wireshark) en una red pública puede interceptar y leer toda la información fácilmente.

4.2 HTTPS (Hypertext Transfer Protocol Secure - Puerto 443)

Versión blindada de HTTP que integra protocolos criptográficos avanzados para garantizar tres pilares de la seguridad informática: Confidencialidad (nadie puede leer los datos interceptados), Integridad (los datos no pueden ser alterados en tránsito) y Autenticidad (se verifica que el servidor web sea legítimo mediante certificados digitales emitidos por Autoridades de Certificación confiables).

4.3 El Proceso de Negociación: Handshake TLS 1.3

Secuencia de pasos criptográficos iniciales que ejecuta el navegador antes de descargar una página web segura:

  • 1. Client Hello / Server Hello: El navegador y el servidor acuerdan las versiones de cifrado y algoritmos matemáticos compatibles.
  • 2. Intercambio de Certificados: El servidor presenta su certificado digital oficial firmado por una entidad certificadora de confianza.
  • 3. Generación de Claves Simétricas: Ambas partes generan claves criptográficas únicas y temporales de sesión mediante intercambio Diffie-Hellman para cifrar todo el tráfico posterior con altísima velocidad y seguridad.

5. Dispositivos de red y medios de transmisión

Una red de computadoras necesita distintos dispositivos para conectar equipos, dirigir el tráfico y proporcionar acceso a los servicios. Cada dispositivo cumple una función diferente dentro de la infraestructura.

Switch

Conecta varios dispositivos dentro de una red local (LAN) y utiliza direcciones MAC para enviar las tramas hacia el puerto correspondiente.

Router

Interconecta redes diferentes y decide por qué ruta deben avanzar los paquetes IP para llegar a su destino.

Access Point

Permite que dispositivos inalámbricos se incorporen a una red mediante Wi-Fi y se comuniquen con la infraestructura cableada.

Módem

Adapta la comunicación entre la red local y la tecnología utilizada por el proveedor de Internet para proporcionar conectividad.

5.1 Medios de transmisión

  • Cable UTP: medio de cobre muy utilizado en redes Ethernet por su bajo costo y facilidad de instalación.
  • Fibra óptica: transmite información mediante pulsos de luz y permite altas velocidades y grandes distancias con baja pérdida.
  • Wi-Fi: utiliza ondas de radio para conectar dispositivos sin necesidad de un cable físico.
Ejemplo práctico: en una red doméstica, el teléfono y la computadora pueden conectarse por Wi-Fi al router, mientras que otros equipos pueden utilizar Ethernet. El router sirve como punto de conexión entre la red local y otras redes, incluido Internet.

6. Puertos, TCP y UDP

Las direcciones IP identifican dispositivos en una red, pero una computadora puede ejecutar muchos servicios al mismo tiempo. Los puertos permiten identificar qué servicio o aplicación debe recibir los datos.

6.1 Puertos conocidos

  • HTTP — puerto 80: comunicación web sin cifrado.
  • HTTPS — puerto 443: comunicación web protegida mediante TLS.
  • DNS — puerto 53: resolución de nombres de dominio.
  • SSH — puerto 22: administración remota segura.
  • FTP — puertos 20/21: transferencia de archivos mediante el protocolo FTP.

6.2 TCP frente a UDP

TCP establece una comunicación orientada a conexión y comprueba la entrega y el orden de los datos. UDP reduce la sobrecarga y no establece una conexión de la misma manera, por lo que resulta útil cuando la rapidez es prioritaria, como en ciertos servicios multimedia, juegos y comunicaciones en tiempo real.

7. Seguridad básica en redes

La conectividad también introduce riesgos. Una red segura debe proteger los equipos, las credenciales y la información que circula entre los dispositivos.

7.1 Principios fundamentales

  • Confidencialidad: solo las personas autorizadas deben poder acceder a la información.
  • Integridad: los datos deben mantenerse correctos y no ser modificados sin autorización.
  • Disponibilidad: los servicios y recursos deben permanecer accesibles cuando sean necesarios.

7.2 Medidas recomendadas

  • Utilizar contraseñas largas y únicas.
  • Mantener actualizado el sistema operativo y el software de red.
  • Activar cifrado y HTTPS cuando esté disponible.
  • Proteger la red Wi-Fi con una configuración de seguridad moderna.
  • Evitar introducir contraseñas en sitios web que no utilicen HTTPS.

8. Conceptos complementarios: LAN, WAN, Internet e Intranet

  • LAN (Local Area Network): red que cubre un área limitada, como una casa, laboratorio u oficina.
  • WAN (Wide Area Network): red que conecta redes a grandes distancias geográficas.
  • Internet: conjunto mundial de redes interconectadas que utilizan protocolos comunes para comunicarse.
  • Intranet: red privada que utiliza tecnologías similares a Internet, pero restringida a una organización.

Comprender estas diferencias permite analizar una red desde distintos niveles: los dispositivos físicos, el direccionamiento, los protocolos, los servicios y las medidas de seguridad trabajan conjuntamente para transportar información desde un origen hasta un destino.

9. Ejemplo de recorrido de una página web

Cuando un usuario escribe una dirección web en el navegador, intervienen varios procesos antes de que aparezca la página:

  1. El navegador identifica el dominio solicitado.
  2. El sistema consulta DNS para obtener la dirección IP asociada.
  3. El dispositivo establece la comunicación con el servidor correspondiente.
  4. Si se utiliza HTTPS, se realiza la negociación TLS para proteger la comunicación.
  5. El navegador envía una solicitud HTTP y recibe la respuesta del servidor.
  6. El navegador interpreta los recursos recibidos y muestra la página al usuario.
> RESUMEN DEL RECORRIDO:
DOMINIO → DNS → IP → ROUTER → INTERNET → SERVIDOR → HTTPS/TLS → RESPUESTA → NAVEGADOR
